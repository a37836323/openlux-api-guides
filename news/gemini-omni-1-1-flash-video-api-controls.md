# Gemini Omni 1.1 Flash 视频 API 控制指南：场景延展、首尾帧与 4K 输出

**结论先说：**Gemini Omni 1.1 Flash 适合需要“先快速试错、再生成高分辨率成片”的视频工作流。开发者可以通过 Gemini API 在 Google AI Studio 中使用，也可以通过 Gemini Enterprise Agent Platform 的 Agent Platform API 接入。不过，具体账号权限和入口状态仍应在官方文档中确认，不能只根据新闻页面推断所有账号都已可用。

本文面向三类读者：

- 需要把 AI 视频生成接入应用的开发者；
- 正在做故事板、广告片或连续镜头工具的产品团队；
- 需要控制视频延展、首尾帧、参考视频和最终分辨率的创作者。

> **官方发布事实：**Google DeepMind 于 2026 年 8 月 27 日发布 Gemini Omni 1.1 Flash，介绍了场景延展、首尾帧过渡、360p 草稿和 1080p/4K 输出等能力。  
> **作者建议：**先用低分辨率完成提示词和镜头验证，再切换到最终输出规格，避免在创意尚未稳定时消耗高分辨率生成资源。

## 一、先确认接入入口与模型标识

官方材料给出的两个开发入口是：

1. **Gemini API + Google AI Studio**
2. **Gemini Enterprise Agent Platform + Agent Platform API**

官方示例使用的模型标识为：

```text
gemini-omni-1.1-flash
```

不要仅凭模型名称拼接接口地址、请求字段或 SDK 版本。当前材料明确给出了模型名、交互续接字段和分辨率字段，但没有完整列出认证方式、限额、地区可用性或价格表。因此，正式接入前应到相应的官方开发者文档确认：

- 当前账号是否能看到该模型；
- 所选 API 产品是否开放视频能力；
- 视频输入、首尾帧和输出分辨率对应的请求格式；
- 任务状态查询、错误处理和结果下载方式；
- 计费与配额规则。

OpenLux 当前公开目录快照没有匹配到该模型，因此不能用目录结果证明它已经在某个第三方 API 目录中上线；验证入口为：https://api.openlux.ai/register?channel=c_lkv0gzwj&utm_source=openlux_api_guides&utm_medium=owned_content&utm_campaign=gemini-omni-1-1-flash-video-api-controls&utm_content=footer

## 二、场景延展：用交互 ID 继续既有视频

场景延展的作用，是根据此前视频继续生成后续片段。官方说明，Gemini Omni 1.1 Flash 最多会分析此前视频的 **10 秒上下文**，并可以按照 **10 秒增量**延展，累计长度最多达到 **40 秒**。

这几个数字需要分开理解：

- **10 秒上下文**：模型用于理解此前内容的上下文上限；
- **10 秒增量**：一次延展可以按这个长度增加；
- **40 秒累计长度**：连续延展后的总长度上限。

它们并不代表任意视频都能自动获得完全一致的角色、布景或动作。实际工作流仍应检查人物位置、镜头方向、道具状态和叙事连贯性。

官方示例通过 `previous_interaction_id` 继续此前的视频交互，示例结构如下：

```python
from google import genai

client = genai.Client()

interaction = client.interactions.create(
    model="gemini-omni-1.1-flash",
    previous_interaction_id=previous_video_interaction.id,
    input=[
        {
            "type": "text",
            "text": "Continue the scene."
        }
    ],
    response_format={
        "resolution": "360p"
    },
)
```

这段示例明确展示了三点：

- 使用 `gemini-omni-1.1-flash`；
- 通过 `previous_interaction_id` 关联此前视频交互；
- 在 `response_format` 中指定 `360p`。

材料没有提供首帧、尾帧或视频参考的完整字段名，所以不应直接猜测请求结构。需要实现这些能力时，应以官方文档、Cookbook 和 prompting guide 的当前格式为准。

## 三、首尾帧：适合控制镜头起点和终点

Gemini Omni 1.1 Flash 支持指定视频的第一帧和最后一帧，让模型生成两帧之间的连续视频。这个能力适合以下场景：

- 镜头从一个人物近景移动到另一个人物；
- 画面从房间一侧绕到另一侧；
- 镜头从现实场景过渡到屏幕或另一个空间；
- 需要控制循环视频的开始和结束状态；
- 已有设计稿，但希望补齐中间的镜头运动。

使用时，建议把首帧和尾帧当作“硬约束”，把运镜方式放进文字提示中。例如，先明确画面中必须保留的人物、物体和环境，再描述推近、拉远、环绕或横摇等运动。

> **作者建议：**首尾帧之间差异过大时，不要只写“平滑过渡”。应进一步说明镜头路径、主体变化顺序和“单一连续镜头”等要求，并在低分辨率下先检查是否出现跳切、主体消失或空间关系突变。

首尾帧功能解决的是“从哪里开始、到哪里结束”的控制问题，不等同于对每一帧进行精确动画编辑。对于需要逐帧动作约束的场景，仍应在应用层增加结果检查和必要的后期处理。

## 四、360p、720p、1080p 与 4K：如何安排生成阶段

官方材料将 360p 定位为快速预览规格，并以 Omni 1.1 的标准 720p 作为对比：

| 使用阶段 | 建议分辨率 | 官方已披露的信息 | 适合验证的内容 |
|---|---:|---|---|
| 故事板与提示词迭代 | 360p | 相比标准 720p，生成速度最高可提升 60%，成本为其三分之一 | 构图、动作方向、镜头节奏、提示词变化 |
| 中间版本检查 | 720p | 官方将其作为标准对比规格 | 画面连续性、角色位置、场景细节 |
| 最终输出 | 1080p | 支持生成高分辨率视频 | 成片清晰度和细节表现 |
| 高分辨率交付 | 4K | 支持生成 4K 输出 | 专业制作所需的高分辨率版本 |

“最高可提升 60%”是基于系统吞吐量的官方数据，不应直接理解为每个请求都能减少 60% 的等待时间。“成本为三分之一”是相对于标准 720p 的相对说法，材料没有给出具体价格，因此不能据此计算实际账单。

一个更稳妥的流程是：

1. 固定素材和主要提示词，先生成 360p；
2. 只改变一个变量，例如运镜、动作或环境；
3. 并排比较多个草稿，挑出叙事和镜头关系更稳定的版本；
4. 确认场景延展或首尾帧过渡没有明显问题；
5. 再选择 1080p 或 4K 进行最终生成。

不要把 360p 草稿当作最终画质的完整代表。草稿阶段主要用于筛选创意和镜头逻辑，最终分辨率仍需单独检查细节、边缘和主体一致性。

## 五、视频参考输入：控制角色和动作时要注意长度

官方表示，模型可以在多模态输入中引用最长 **3 秒**的视频。官方示例将舞者视频作为动作参考，再结合角色图像和场景图像生成连续镜头。

这类输入适合验证：

- 某个角色应采用哪种动作风格；
- 角色如何在空间中移动；
- 现有短视频中的动作节奏能否迁移到新角色；
- 参考视频与静态角色图像组合后的连续性。

但“支持最长 3 秒参考视频”不代表模型会逐动作精确复制，也没有材料证明角色一致性在所有场景下都能保持。实际验证时，应控制输入变量：先只使用一个短参考视频和一个角色，再逐步增加其他素材。

对于角色一致性要求较高的项目，可以建立专门的测试集，检查以下项目：

- 面部或外形是否在镜头中发生明显变化；
- 服装、颜色和配件是否保持；
- 动作是否符合参考视频的主要节奏；
- 多个主体同时出现时是否发生互换；
- 是否出现不需要的切镜或新增物体。

## 六、一个可执行的接入与验证流程

### 第一步：确认官方入口

在 Google AI Studio 或 Agent Platform API 文档中确认模型可见性、账号权限和当前请求格式。不要先按新闻中的能力清单开发全部功能，再回头处理入口差异。

### 第二步：验证基础生成

使用模型标识 `gemini-omni-1.1-flash` 进行最小化请求。先确认文本提示和基本视频返回流程正常，再加入交互续接、首尾帧和参考视频。

### 第三步：验证场景延展

保存第一次视频交互返回的交互标识，然后使用 `previous_interaction_id` 请求“继续场景”。测试时记录：

- 延展是否按预期增加；
- 前后镜头中的人物和背景是否连续；
- 多次延展后是否出现累计长度限制；
- 文字提示改变后，模型是否按要求转向新的叙事分支。

### 第四步：验证首尾帧

准备一组起始帧和结束帧，先在 360p 下检查镜头路径。确认请求格式后，再测试推拉、环绕、横摇和循环镜头等不同运镜。

### 第五步：验证参考视频

使用不超过 3 秒的参考视频，先测试单一角色和单一动作。若结果稳定，再加入更多图像或视频素材，并记录每次输入的变化。

### 第六步：切换最终分辨率

在创意、镜头和素材关系稳定后，分别验证 1080p 或 4K 输出。最终验收不能只看分辨率，还要检查运动连续性、主体外观、画面构图和是否出现意外内容。

## 七、上线前检查清单

- [ ] 已在 Google AI Studio 或 Agent Platform API 文档中确认入口和权限；
- [ ] 模型标识使用 `gemini-omni-1.1-flash`；
- [ ] 已用 `previous_interaction_id` 验证视频延展；
- [ ] 场景延展按 10 秒增量规划，累计长度不超过 40 秒；
- [ ] 需要连续运镜时，已准备并验证首帧和尾帧；
- [ ] 参考视频长度控制在 3 秒以内；
- [ ] 草稿阶段优先使用 360p；
- [ ] 已区分 360p 吞吐量数据与单次请求实际等待时间；
- [ ] 最终版本根据交付需求选择 1080p 或 4K；
- [ ] 没有把相对成本信息当作具体价格；
- [ ] 已对角色、动作、镜头连续性和异常画面进行人工或程序化检查。

总体而言，Gemini Omni 1.1 Flash 的价值不只是提高输出分辨率，而是把视频工作流拆成了几个可控制环节：用 360p 快速探索，用交互 ID 延展场景，用首尾帧约束镜头起止，用短视频参考补充动作和视觉上下文，最后再生成 1080p 或 4K 版本。真正接入时，应把这些能力分别验证，而不是一次性假设它们会自动组合成稳定成片。
