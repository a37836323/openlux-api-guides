# IBM Granite PatchTST-FM-r2 上线：如何用开源权重部署零样本时间序列预测

**结论：**如果你的业务有规则采样的需求、价格、能耗、流量或遥测时间序列，希望先以预训练模型进行零样本预测，IBM Granite PatchTST-FM-r2 可作为离线评估对象。它支持最长 8192 步上下文、可变预测长度，并能同时输出点预测与指定分位数预测。部署前应重点验证三件事：数据频率和字段是否符合管道要求、8192 步上下文是否足以覆盖业务周期、双许可证中哪一种适合组织的使用与分发场景。

本文面向需要安装、调用和评估 `ibm-granite/granite-timeseries-patchtst-fm-r2` 的数据工程师、算法工程师及负责模型治理的技术负责人。

## 官方发布事实：模型能力与边界

IBM 于 2026 年 9 月 9 日发布 PatchTST-FM-r2，Hugging Face 模型标识为：

```text
ibm-granite/granite-timeseries-patchtst-fm-r2
```

官方披露该模型约有 3.85 亿参数，最长支持 8192 个时间步的输入上下文，并允许按任务设置预测长度。它既可提供点预测，也可输出 99 个分位数，以表达未来值的预测分布和不确定性区间。

对于实际部署，这些能力应理解为接口与结构约束，而不是生产效果承诺。例如：

| 维度 | 已核验信息 | 部署时应验证的问题 |
|---|---|---|
| 模型规模 | 约 3.85 亿参数 | 目标运行环境是否能满足本地加载与推理资源需求 |
| 输入上下文 | 最长 8192 步 | 上下文能否覆盖日、周、月等关键业务周期 |
| 预测长度 | 可灵活设置 | 预测窗口是否与补货、排班、告警或调度周期对应 |
| 输出形式 | 点预测与 99 个分位数 | 下游系统是否能使用区间而非仅使用单值 |
| 推理方式 | 支持零样本预测 | 自有数据上是否能达到可接受的离线误差 |
| 发布材料 | 提供权重、架构、推理流程和复现实验代码 | 团队是否能复现最小推理链路并纳入版本管理 |

“零样本”在这里指无需先针对当前数据集进行任务专用训练即可生成预测，不代表无需验证数据适配性。数据频率变化、缺失模式、目标定义变化以及异常值，都可能改变自有场景中的结果。

## 先判断你的数据是否适合接入

官方示例采用带时间戳和目标列的规则采样时间序列，并通过 `timestamp_column`、`target_columns` 与 `freq` 明确数据含义。接入前，建议先完成以下检查：

- 每条序列有可解析的时间戳列，且时间顺序正确。
- 目标列是数值型，业务含义在训练历史和预测期内保持一致。
- 数据采样频率稳定，并能明确填写如 `1h` 的频率。
- 数据存在足够连续的最近历史；首次验证可从最近 512 个样本开始。
- 多个实体混合在同一张表时，先明确是否需要标识列，并在管道中配置 `id_columns`。
- 缺失值、停机数据、口径切换和极端异常应先被标记，不能把预处理问题误判为模型误差。
- 预测目标与预测时点严格对齐，避免把未来已知数据误放进历史输入。

最长 8192 步是上限，不是每个任务都应使用的默认值。较短上下文更适合做快速连通性验证；更长上下文则应通过滚动回测确认其是否确实提升业务关心的预测窗口表现。

## 安装并运行官方推理流程

官方示例要求安装 `granite-tsfm>=0.3.9`，并使用 `PatchTSTFMForPrediction` 与 `TimeSeriesForecastingPipeline` 加载模型。以下代码仅保留官方材料明确展示的参数：

```python
import pandas as pd
from tsfm_public import PatchTSTFMForPrediction, TimeSeriesForecastingPipeline

model = PatchTSTFMForPrediction.from_pretrained(
    "ibm-granite/granite-timeseries-patchtst-fm-r2"
)

df = pd.read_csv(
    "your_timeseries.csv",
    parse_dates=["timestamp"],
)

pipe = TimeSeriesForecastingPipeline(
    model=model,
    id_columns=[],
    timestamp_column="timestamp",
    target_columns=["target"],
    max_context_length=model.config.context_length,
    context_length=512,
    prediction_length=64,
    impute_method=None,
    quantile_levels=[0.1, 0.5, 0.9],
    explode_forecasts=True,
    freq="1h",
)

forecast = pipe(df.iloc[-512:])
```

安装命令如下：

```bash
pip install "granite-tsfm>=0.3.9"
```

将 `timestamp`、`target`、`1h`、`512` 和 `64` 替换为实际场景的列名、频率、历史窗口和预测窗口。首次运行时，不要同时扩大上下文、延长预测长度、增加目标列和改变清洗策略；一次只改变一个变量，才能定位误差变化的原因。

## 如何读取点预测和分位数预测

点预测适合需要单一计划值的场景，例如生成基础需求计划或作为后续规则系统的输入。分位数预测则适合需要处理不确定性的决策，例如库存安全量、容量预留和告警阈值。

官方示例设置了 `0.1`、`0.5`、`0.9` 三个分位数，可将其用作下界、中位预测和上界的初始检查。这里的区间应被看作模型给出的预测分布信息，而不是业务必然落入的承诺范围。

建议把输出接入以下验证流程：

1. 固定一个历史截止时间，只向模型提供该时点之前的数据。
2. 生成与真实业务窗口一致的预测长度。
3. 与截止时间之后实际发生的值对齐，分别计算点预测误差和区间覆盖情况。
4. 按实体、时段、节假日、峰谷负载或异常状态切分结果，观察误差是否集中。
5. 对比不同 `context_length` 和 `prediction_length` 组合，选择符合业务成本的设置。
6. 将分位数输出映射到明确决策，例如保守备货使用较高分位数，而非只展示图表。

## 如何正确看待 GIFT-Eval 排名

**官方发布事实：**截至 2026 年 9 月 8 日，官方材料称 PatchTST-FM-r2 在 GIFT-Eval 的“可复现零样本模型”类别中，CRPS 与 MASE 均排名第二。两项指标均是数值越低越好。

这一结果可用于判断模型值得进入候选评估池，但不能直接替代生产验收。排行榜数据集、业务数据的频率、预测跨度、缺失情况、目标分布和决策成本通常不同。尤其在价格、需求和遥测场景中，平均误差相近的模型，可能在高峰期、突变期或关键实体上的表现差异很大。

**作者建议：**将排行榜视为外部可复现证据，而将自有时间切分回测视为上线依据。至少保留一个从未参与调参的最终时间段，用于确认选择的上下文、预测窗口与分位数策略没有只适配历史实验集。

## 商业使用前的许可证与治理审查

**官方发布事实：**模型采用 Apache-2.0 与 OpenMDW 1.0 双许可证，使用者可以选择其中一种。官方同时提供模型权重、架构、推理流程和复现实验代码。

**作者建议：**许可证选择不能只由研发团队口头决定。应由法务、开源办公室或负责软件交付的团队审查拟采用许可证的完整文本，并记录选择结果。至少确认以下问题：

- 组织是内部使用、对客户提供托管服务，还是向外部分发模型或衍生物。
- 模型权重、代码、容器镜像与业务数据分别由哪些许可证、合同或治理规则约束。
- 是否需要在分发产物中保留许可证、声明或其他通知。
- 自有数据是否含个人信息、受监管数据、客户机密或跨境传输限制。
- 模型版本、依赖版本、评估数据切分和批准记录是否可追溯。

Apache-2.0 或 OpenMDW 1.0 的适用性需要以完整许可文本和组织实际使用方式为准，不能仅依据“开源”或“商业友好”等概括性描述作出结论。

- [ ] 用单个目标列和最近 512 个规则采样样本跑通推理。
