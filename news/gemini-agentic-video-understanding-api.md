# Gemini API 上线 Agentic Video：如何启用并降低长视频分析 Token 消耗

**结论：**如果你的 Gemini API 视频任务包含长视频内容检索、快速动作识别、异常片段检查或重复对象计数，值得在测试环境中把视频输入的 `processing` 改为 `"agentic"`，并与原有固定 FPS 处理进行对照。Google DeepMind 已宣布该能力支持 Gemini 3.7 Flash、Gemini 3.6 Flash 和 Gemini 3.5 Flash-Lite；它没有额外功能费，但仍按标准 Gemini API Token 价格计费。

本文适合已通过 Gemini API 处理上传视频或 YouTube 视频 URI 的开发者、技术负责人和成本管理人员。重点是建立迁移与验证方法，而不是把官方基准结果直接视为生产环境结论。

## 官方发布事实：Agentic Video 的工作方式

**官方发布事实：**Google DeepMind 于 2026 年 9 月 1 日宣布推出 agentic video understanding，本文简称 Agentic Video。该能力可经由 Google AI Studio 和 Gemini Enterprise Agent Platform 中的 Gemini API 使用。

传统静态视频处理通常按固定帧率读取视频。官方材料说明，其默认处理速率为 1 FPS，并且可通过 API 调整。固定 FPS 的问题在于：

- 提高帧率可能保留更多快速动作和短暂状态变化，但输入 Token 可能随之增加；
- 降低帧率可以控制输入量，却可能遗漏关键画面；
- 对数十分钟或多小时视频进行高密度全量分析，成本压力会更明显。

Agentic Video 的设计方式不同。模型可以根据用户问题，动态决定需要查看哪些时间段、以何种速度检查，以及优先使用视频帧、音频还是转录文本。官方称，它会借助内部视频工具加载相关片段，而不是始终以固定 FPS 均匀扫描完整视频。

因此，它更适合“先找到候选时间窗，再检查细节”的视频问题。例如，从一段长课程中找出某个概念的讲解位置，或先定位可疑片段，再回看高速动作与画面变化。

## 支持范围、输入形式与计费

下表区分了官方已经发布的信息，以及团队上线前仍应自行验证的部分。

| 项目 | 官方发布事实 | 对实施的含义 |
|---|---|---|
| 支持模型 | Gemini 3.7 Flash、Gemini 3.6 Flash、Gemini 3.5 Flash-Lite | 迁移与模型对比应限定在这三个模型中 |
| API 使用位置 | Google AI Studio、Gemini Enterprise Agent Platform | 先确认当前项目的 Gemini API 接入环境 |
| 视频输入 | 视频上传、YouTube 视频 URI | 可用于文件视频与 YouTube 链接工作流 |
| 启用配置 | 视频输入的 `processing` 设置为 `"agentic"` | 需要修改视频输入对象，不是只调整提示词 |
| 功能费用 | 不收取额外功能费 | 仍按标准 Gemini API Token 价格结算 |
| 官方基准结论 | Token 消耗最高减少 88%，分析成本最高降低 66%，准确率最高提升 7% | 只能作为测试方向，不应直接写入内部预算或 SLA |
| 官方列举场景 | 亚秒级片段检索、长视频检索、异常检测、动作与对象计数 | 应选择与自身业务相近的样本进行评估 |

需要特别区分：没有额外功能费，不代表视频分析不产生费用。实际支出仍取决于调用的 Token、账户适用的标准价格、重试次数及人工复核成本。

## 如何启用 Agentic Video

**官方发布事实：**启用该能力的关键是，在视频输入配置中加入：

```json
"processing": "agentic"
```

官方示例使用 `gemini-3.7-flash`、YouTube 视频 URI，以及 `interactions.create` 调用方式。对于已有视频处理代码，建议先做最小改动：

1. 保持原有视频文件或 YouTube URI 不变；
2. 保持模型、提示词和输出格式不变；
3. 仅在实验组的视频输入中设置 `processing: "agentic"`；
4. 记录输出内容、Token 消耗、调用成本和人工判定结果；
5. 确认处理模式的影响后，再比较不同支持模型。

不要在同一轮实验中同时更换模型、提示词、视频样本和处理方式。否则结果即使发生变化，也难以判断是 Agentic Video、模型差异还是提示词改写造成的。

## 哪些任务值得优先迁移验证

**官方发布事实：**Google DeepMind 将 Agentic Video 的适用方向列为亚秒级检索、长视频“针在草堆中”搜索、异常检测，以及动作和对象计数。

### 长视频知识检索

适用于培训录像、会议、课程、讲座、访谈和多小时录制内容。典型问题包括：“某个观点在什么位置提出”“演示中如何完成某步骤”“视频中是否讨论过某项条件”。

这类任务的评估不能只看回答是否通顺。还应检查答案是否与视频内容一致，是否能覆盖问题要求的多个条件，以及是否遗漏只出现一次、且位置较靠后的信息。

### 快速动作与短暂状态变化

官方提到亚秒级时刻定位和动态帧率检查。此类任务包括快速手势、镜头切换、瞬时状态变化、高速重复动作等。

**作者建议：**测试集应加入低 FPS 容易遗漏的片段，例如持续时间很短、背景复杂、相似动作连续发生的视频。仅使用动作明显、节奏较慢的案例，难以体现两种处理模式的实际差异。

### 异常检测

对于仅在少数时间窗出现的异常，静态均匀扫描未必是成本更合适的方案。官方表示，Agentic Video 可以对值得关注的时间段以较高 FPS 再次检查。

验证异常检测时，至少分别记录：

- **发现率：**实际异常是否被识别；
- **误报情况：**正常片段是否被标记为异常；
- **定位可用性：**输出是否足以帮助人工快速复核。

只看发现了多少异常，会忽略误报导致的审核负担。

### 动作和对象计数

计数任务的风险不仅包括漏计，还包括同一对象跨帧重复计入、遮挡造成的判断偏差，以及快速动作边界不清晰。

**作者建议：**为每个测试视频建立人工标注结果，记录真实数量，并计算模型输出与标注值之间的差值。同时保留错误案例，按“漏计、重复计入、对象混淆、时间段判断错误”等类型归档，便于后续调整提示词与部署模型。

## 如何理解官方的 Token 与成本降幅

**官方发布事实：**Google DeepMind 表示，在标准视频分析基准中，Agentic Video 最高可减少 88% Token 消耗、最高降低 66% 分析成本，并最高提升 7% 准确率；官方还指出，长视频场景中的效率收益更明显。

这些数据说明该能力值得验证，但不等于每个业务视频都能获得相同幅度的变化。你的结果可能受到以下因素影响：

- 视频长度、分辨率、清晰度和内容密度；
- 问题是全局总结、事实检索，还是短时刻定位；
- 视频中视觉、音频和文本信息各自的重要程度；
- 所选模型及其在你的任务集上的表现；
- 是否存在失败重试、人工审核和后处理步骤。

建议使用下面的成本框架，而不是只比较单次 API 调用：

> 单任务总成本 = 视频分析调用成本 + 重试成本 + 人工复核成本 + 后处理成本

如果某种处理方式降低了 Token，但增加了人工确认次数，整体成本未必下降。反过来，如果它让异常定位或计数结果更便于复核，调用费用的变化也应放在完整业务流程中判断。

## 迁移与验证步骤

### 第一步：建立有代表性的样本集

按业务场景分层抽样，而不是随机挑选少量视频。样本可包含：

- 短视频、长视频与多小时视频；
- 视觉信息为主、语音信息为主、混合信息视频；
- 正常案例与异常案例；
- 慢动作与快速动作；
- 简单背景与遮挡、复杂背景案例。

长视频检索任务应包含“答案仅出现一次且位置靠后”的样本；计数任务则应加入对象重复出现、遮挡和高频动作样本。

### 第二步：建立明确对照组

建议至少建立两组调用：

- **基线组：**当前固定 FPS 或既有静态视频处理方案；
- **实验组：**相同视频、相同模型、相同提示词，仅设置 `processing: "agentic"`。

如果现有系统没有明确指定 FPS，也应记录当前调用配置和实际行为，避免把不透明的基线与新模式进行比较。

### 第三步：记录四类数据

每次调用至少记录：

1. 视频标识、视频时长、任务类型；
2. 使用的模型和处理模式；
3. 模型输出与人工判定结果；
4. Token 消耗、按账户价格计算的调用费用、重试次数及人工复核情况。

对于需要审计或持续优化的业务，还应保存问题文本、标注规则、预期答案和错误类别。

### 第四步：按任务类型作出部署决定

不要只看整体平均 Token 或平均成本。应分别分析：

- 长视频检索的答案完整性是否保持；
- 快速动作任务的漏检是否减少；
- 异常检测的发现率与误报是否符合业务要求；
- 计数任务与人工标注之间的偏差是否缩小；
- 哪个支持模型更符合当前任务的质量与成本约束。

**作者建议：**当实验组在关键质量指标上不弱于基线，并且单任务总成本更符合目标时，再逐步扩大流量。对于审核、安防或其他高影响任务，可保留基线方案作为抽样复核或回退路径。
